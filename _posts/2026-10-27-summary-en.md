### [webframe runs a web page like a program, evaluated as scraper and sandbox](https://simonwillison.net/2026/Oct/26/webframe-evaluation/) ⭐️ 6.0/10

Simon Willison published a research note testing webframe, a small tool by Jeff Lindsay, written in the Go programming language, that takes a web address or a local file and runs it in a hidden browser window, printing the page&\#x27;s console output \(messages a page logs for developers\) to the terminal and any errors to a separate error stream. webframe borrows the browser already installed on the machine — Safari&\#x27;s engine on macOS, WebKitGTK on Linux, Edge&\#x27;s WebView2 on Windows — instead of shipping its own, which makes it much smaller than Willison&\#x27;s own shot-scraper tool, which relies on Playwright, a separate browser-automation package. Willison had an AI model, Claude Opus 5.5, try the tool out, build small prototypes, and judge it both as a way to scrape web pages and as a sandbox \(an isolated environment for running code\). The posted excerpt ends before those findings, so the evaluation&\#x27;s actual conclusions are not yet stated.

rss · Simon Willison · Oct 26, 16:15

**「Background」** A browser that runs without ever showing a window is called a &quot;headless&quot; browser, and it is the standard way to automate scraping a page or to open a suspicious one with less risk to your own machine. Most such tools — including shot-scraper, an earlier tool by the same author — ship their own copy of a browser engine, which makes them large. webframe goes the other way: it drives whatever browser the operating system already has installed, through a small helper library called glaze that is written in Go \(a programming language\).

**「What it means in practice」** Because webframe uses whatever browser the machine already has rather than a bundled engine, the same script can behave differently across macOS, Linux, and Windows, and its behavior shifts when the installed browser updates — a compatibility point to check before relying on it for repeatable scraping. Anyone weighing it as a sandbox should note that the isolated code runs inside the user&\#x27;s everyday browser engine, so the isolation is only as strong as that browser&\#x27;s own protections.

rss · Habr AI · Oct 26, 12:11

**「Background」** GGUF is a file format used by llama.cpp, a free program for running AI models on a personal computer. Model creators usually publish their original weight files on Hugging Face in the safetensors format, and turning those files into GGUF normally means repackaging them first and then quantizing them, which reduces the precision of the numbers stored in the model so the file takes up less memory. Ready-made GGUF versions exist for many models, but not every model or every compression level, which is the gap the guide&\#x27;s script is meant to fill.

**「What it means in practice」** This matters when the model you want to run locally exists only as raw Hugging Face weights, since those will not load in the common GGUF-based local runners without a conversion step. The trade-off then falls on the user: a lower level such as Q4\_K\_M gives a smaller file that fits on modest hardware but can answer worse than Q8\_0, and the conversion needs the original weights plus enough disk space to hold both versions before the cleanup runs.
